# ADR-0001 最初の実行可能な縦切り

- 状態: 公開レビュー用草案
- 日付: 2026-08-16
- 対応: QF-MVS01-ITR-001 / QF-MVS01-TST-001 / QF-UML-MVS01-001

## 決定

最初の反復では、`Question`状態機械、ASP.NET Core Minimal API、インメモリ実装、Domain/API自動テストを一組として作る。

外部NuGetパッケージを使わず、.NET共有フレームワークだけでビルド・実行する。テストは終了コードを返す小さなランナーとし、Kestrelを実際に起動してHTTP境界を検査する。

## 理由

- 状態遷移、自己承認禁止、所有者制御、版競合を、DBやクラウド設定より先に固定できる。
- 外部パッケージ取得不能な環境でも、一般の方が同じ試験を再現できる。
- 仕様変更時に、要求ID・実装・テストIDを同じ変更として確認できる。
- PostgreSQLやOIDCを追加する前に、間違いを小さな範囲で検出できる。

## セキュリティ上の決定

テスト用ヘッダー認証は `Testing` 環境でのみ有効とする。通常起動では管理APIを401に倒し、テスト用認証が誤って本番入口にならないようにする。

本文は監査へ保存しない。公開DTOは所有者、内部version、審査理由、監査情報を持たない。

## 結果と制約

インメモリ実装は再起動で消えるため、本番データストアではない。次反復では、公開API契約とDomainテストを維持したままPostgreSQL実装へ差し替え、監査と状態更新を同一トランザクションにする。

OIDC/MFA、スマートフォンUI、暗号化バックアップ、リージョン復旧は、このADRの完了条件には含めない。暗号化・隔離復元は後続ADR-0003で追加し、実クラウドDRはなお未実装として追跡表へ明記する。
